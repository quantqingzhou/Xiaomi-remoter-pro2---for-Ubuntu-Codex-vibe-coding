# 客户端更新后恢复

本项目专为 Linux 版 Codex 用户设计。桌面客户端更新可能覆盖 `native/dictation-ducking` 的播放保护；这时桥接会暂停触发 F5，避免再次启动客户端原有的听写降音量功能。出现这个现象不等于蓝牙配对或遥控器按键配置丢失。

`alpha.5` 增加了独立的只读诊断。恢复仍使用原有 `protect-client` 命令，不会在后台自动改客户端、重配蓝牙或重启音频服务。

## 第一步：只读检查

在已更新至 `alpha.5` 或更新版本的源码目录运行：

```bash
/usr/bin/python3 -B scripts/doctor.py --client-only
```

默认检查 `/usr/lib/chatgpt/resources/native/dictation-ducking`。安装位置不同时，加上 `--helper /绝对路径/native/dictation-ducking`；此路径也必须与桥接配置的 `dictation_helper` 相同。

| 状态 | 含义及下一步 |
| --- | --- |
| `protected` | 当前内容与保护程序相同。继续测试听写；仍无响应时按[故障排查](TROUBLESHOOTING.md)检查焦点、快捷键和实际收音 |
| `known_original` | 当前是已核实原版，保护未生效。首次安装或更新覆盖后都可能出现，按下一节预览并重新应用 |
| `unknown` | 当前文件内容未核实。停止替换，保留文件和备份，提交版本及哈希供重新审查，不绕过校验 |
| `unavailable` | 文件不存在、路径不合要求、是符号链接或无法读取等；先核对实际安装位置和错误提示 |

只有 `protected` 返回退出码 0，其他状态返回 1。诊断不读取项目配置或私有备份，不检查蓝牙、麦克风、服务或实际听写；保护文件有效不等于整个流程已经验收。

## 第二步：对已核实原版重新应用

仅在状态为 `known_original` 时进行。结束听写、保存工作并正常退出桌面客户端，避免旧的降音量辅助进程仍在运行。然后在系统终端执行。

系统目录中的原始备份和元数据属于管理员私有文件，因此更新后的保护预览也可能需要管理员权限：

```bash
sudo /usr/bin/python3 -B scripts/manage.py protect-client
```

核对输出的目标路径与计划，预览成功后执行：

```bash
sudo /usr/bin/python3 -B scripts/manage.py protect-client --apply
/usr/bin/python3 -B scripts/doctor.py --client-only
```

如果客户端及备份位于当前用户有权访问的目录，可省略 `sudo`。使用自定义路径时，上述每条命令都需指定相同的 `--helper /绝对路径/native/dictation-ducking`。

重新应用会校验已有的 `dictation-ducking.xiaomi-codex-original` 和 `dictation-ducking.xiaomi-codex-protection.json`，保留有效备份及文件属性，再原子替换目标文件。备份损坏、权限或属主与记录不符时会拒绝操作；不要删除备份、放宽目录权限或使用旧备份覆盖新客户端来绕过检查。

## 第三步：验证实际使用

确认状态为 `protected`，重新打开客户端并点消息输入框。按住遥控器语音键说话，松开后确认录音停止并出现文字，再按确认键发送。播放音乐时重复几次，另行检查切歌、语音消息和提示音。

运行中的桥接会再次检查保护内容；单纯重新应用保护不需要重新安装桥接、重新配对或重启 PipeWire。此次 `26.1111.21308` 恢复中，运行中的按键服务已即时识别保护，用户验证听写及发送成功。若只读检查通过但仍无波形，继续按实际音频路由排查，不反复替换保护文件。

## 升级本项目与升级客户端的区别

如果源码由 `git clone` 获取，可在没有未处理本地修改的情况下运行 `git pull --ff-only`，或重新下载最新源码到独立目录。本版新增诊断可直接从源码目录使用，不要求重装现有桥接。

更新源码目录不会自动更新已安装的运行文件，也不会自动重新应用客户端保护。本版没有修改按键或重连行为；若以后需要更新已安装桥接，应按[安装与回退说明](../README.md)处理原安装清单和冲突，不能通过删除清单强行覆盖。
