# 状态与故障提示

这是 `alpha.6` 增加的功能。它通过独立的 `xiaomi-codex-status.service` 显示中文桌面通知，帮助判断遥控器为何没有响应；没有托盘图标或常驻悬浮窗。

`alpha.6`的[设置窗口](KEY_SETTINGS.md)还提供蓝牙状态和“状态与日志”面板，复用这里的只读检查。面板可以查看近期服务日志；主动点击“暂停后台”会连同通知服务一起暂停，避免把计划内暂停误报为故障，恢复时按暂停前状态恢复通知。

## 会提示什么

| 提示 | 检测依据与处理方向 |
| --- | --- |
| 连接已断开 | 蓝牙查询明确返回未连接；轻按方向键唤醒，检查电量与连接 |
| 按键设备不可用 | 蓝牙已连接，但没有匹配 MAC、VID/PID、F5 能力且可读取的输入节点；检查权限或重新连接 |
| 音频桥接未就绪 | SayAll 用户服务尚未运行或正在重连；持续异常时查看服务日志 |
| 找不到 SayAll Mic | 音频系统可查询，但不存在名称精确为 `sayall-mic` 的输入设备 |
| 麦克风已静音／音量为零 | 此虚拟麦克风的系统静音或声道音量异常；由用户检查声音设置 |
| 按键桥接未就绪 | 通过本地 socket 无法取得按键服务的就绪状态 |
| 听写播放保护未生效 | 辅助程序恢复成已核实原版；按[客户端更新指南](CLIENT_UPDATES.md)检查并重新应用 |
| 客户端文件需要核实 | 辅助程序内容未知或无法读取；保留现场，不能直接覆盖新版本 |
| 无法检查蓝牙／桥接／麦克风 | 查询失败或超时，不能据此认定设备断开或不存在 |
| 基础连接已恢复 | 已送达的故障通知之后，各项检查恢复正常；仍需实际说话验证收音 |

同一次检查只报告最先发现的障碍，避免掉线同时引出“桥接、麦克风、按键”多条连锁提示。蓝牙恢复后，如果还存在其他障碍，会继续提示当前问题。

## 提示节奏

- 每轮检查完成后等待约 5 秒；外部查询设有超时，实际间隔可能更长。
- 启动后先留出 30 秒，给登录、蓝牙连接和虚拟麦克风创建留时间。
- 基础检查连续异常至少 10 秒才考虑提醒；同一次掉线中故障种类变化不会重置此计时。恢复正常持续至少 5 秒才考虑恢复提示。
- 两次通知尝试至少相隔 30 秒。同一故障持续存在时不重复弹出；正常启动保持安静，短暂异常若没有提醒，也不单独提示恢复。
- 通知使用普通优先级，并请求桌面抑制通知声音；不播放测试音。可复用的通知 ID 用于更新同一条提示。

最终横幅样式、停留时长、提示音与勿扰行为由桌面系统决定。发送成功只表示桌面接受请求，不代表用户一定看到了横幅。

## 安装与启用

本项目安装程序会生成此独立服务，但不自动启用。需要已登录的图形桌面、支持桌面通知的会话，以及 `notify-send`。Ubuntu / Debian 缺少该命令时可自行安装：

```bash
sudo apt install libnotify-bin
```

新安装时，按[主说明](../README.md)完成用户文件安装和桥接验证，再启用提示：

```bash
systemctl --user daemon-reload
systemctl --user enable --now xiaomi-codex-status.service
```

服务随图形会话启动和停止，独立于 SayAll 和按键服务，才能在桥接停止时继续报告状态；它不作为桥接启动的前置条件。已有旧版安装需要按安装清单升级，单纯更新源码目录不会自动新增已安装的服务。

在源码目录可以先测试桌面通知，此命令不需要桥接配置，也不会伪造断连：

```bash
/usr/bin/python3 -B src/status_notifier.py --test-notification
```

已有安装配置时，可以只检查一次，不发送通知：

```bash
/usr/bin/python3 -B src/status_notifier.py --once
```

检查输出中文说明和状态码，全部基础检查通过时返回 0，否则返回 1。默认读取 `~/.config/xiaomi-codex-remote/config.json`，遵循 `XDG_CONFIG_HOME` 和 `XIAOMI_CODEX_CONFIG`。旧原型可以用 `--key-socket /绝对路径/keys.sock` 指定按键服务的实际 socket；不要将某台电脑的路径或地址写入公开源码。

## 暂停、关闭与排查

准备主动停止桥接、卸载或维护设备时，可先暂时停止提示，避免将计划内的停机当作故障：

```bash
systemctl --user stop xiaomi-codex-status.service
```

维护结束后用 `start` 恢复。若要长期关闭或准备卸载，执行：

```bash
systemctl --user disable --now xiaomi-codex-status.service
```

这只关闭提示，原有按键和音频桥接继续运行。修改通知读取的配置后，需要重新启动通知服务。

```bash
systemctl --user status xiaomi-codex-status.service
journalctl --user -u xiaomi-codex-status.service -n 30
```

看不到通知时，先运行测试通知，并检查桌面通知权限和勿扰状态。GNOME 可在顶部时钟的通知列表中查找。通知不要求共享桌面权限，也不会打开远程桌面授权窗口。

## 检测边界

通知服务只查询蓝牙、sysfs、用户服务和音频设备，向现有按键 socket 发送的唯一命令是 `status`，并只读检查客户端保护文件。它不打开录音流、不读取转写内容、不接管输入设备，不改变默认麦克风、输出设备或音量，也不自动重启蓝牙、音频或桥接。

本版不检测实际语音电平、Codex 的音频子进程、应用内部增益或云端转写是否成功。因此，“基础连接已恢复”不能证明实际有声；仍无波形时按[故障排查](TROUBLESHOOTING.md)继续检查。系统虚拟麦克风在空闲时显示 `SUSPENDED` 是正常现象，不会因此报错。

不保证登录前、其他桌面环境或通知被系统屏蔽时能显示提示。更改客户端保护文件、真实断开蓝牙等故障注入不属于安装或启动步骤。
