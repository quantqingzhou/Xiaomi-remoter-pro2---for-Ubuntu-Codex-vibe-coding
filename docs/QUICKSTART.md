# 快速开始

**本项目专为 Linux 版 Codex 用户设计**，帮助用户用中文语音进行 vibe coding。按住小米蓝牙遥控器 2 Pro 的语音键，在 Codex 中听写；松开结束，再按中间确认键发送。返回键在 Codex 和已启用的微信窗口中是退格键，支持长按删除；其他软件中保留原始返回行为。

当前版本为 **0.1.0-alpha.4**。实物原型验证环境是小米蓝牙遥控器 2 Pro（设备识别型号 `RC003`）、Ubuntu 26.04、GNOME Wayland 会话中可被 XWayland 识别的 Codex 窗口，以及 SayAll 0.3.0。新增客户端播放保护已通过程序与回退测试；本机短时实测中，用户确认开始录音时 QQ 音乐没有变小。约 115 秒内的多次听写监测未见播放增益下降；清理旧规则后重新登录或重启的验证、长期稳定性和另一台干净电脑安装仍待完成，详见[验证记录](TESTING.md#客户端播放保护实测)。

微信语音输入是默认关闭的可选扩展，需要自行安装并配置 Fcitx5 Vinput；请单独阅读[微信安装说明](WECHAT.md)。

## 按顺序完成安装

1. 在系统蓝牙设置中配对并信任遥控器，单独安装 [SayAll for Linux](https://github.com/ZXC011/sayall-linux) 0.3.0 及[依赖](../README.md#1-准备依赖并配对)。不需要安装本地语音识别模型。
2. 先完成[客户端播放保护](../README.md#2-先启用客户端播放保护)：普通用户运行下方 `protect-client` 预览；确认后结束听写并正常退出客户端，再应用。系统目录需要管理员权限时使用完整说明中的 sudo 命令，然后重新打开客户端。这是完整方案的必要步骤，未知版本会拒绝执行。
3. 把示例地址换成自己的遥控器地址，预览用户文件安装。确认计划后，按[完整安装说明](../README.md#3-先预览再安装用户文件)停止已有 SayAll，再添加 `--apply` 安装用户文件；此步骤使用普通桌面用户，不用 sudo。
4. 检查并安装生成的[设备权限规则](../README.md#4-安装设备权限规则)，重新连接遥控器。
5. 在 Codex 中把“按住听写”设为 **F5**，然后按[启动说明](../README.md#5-设置-f5启动桥接)启动服务并执行只读诊断。

```bash
/usr/bin/python3 -B scripts/manage.py protect-client
/usr/bin/python3 -B scripts/manage.py install --address AA:BB:CC:DD:EE:FF
```

预览不会写文件或启动服务。不要在尚未确认路径和冲突时跳过预览；旧桥接方案需要先备份和迁移。

## 第一次使用

点一下 Codex 消息输入框，按住遥控器语音键说话，松开后等待文字出现，再按中间确认键发送。窗口焦点检查无法判断窗口内部是否正在编辑消息，因此必须先让输入框获得焦点。

启动桥接后，系统中应出现 **SayAll Mic**，内部名称为 `sayall-mic`。按住语音键时收音，当前方案不提供持续开麦。腾讯会议尚未实测。

## 使用前了解音频边界

默认方案会对已核实的客户端降音量辅助程序进行备份和替换，不修改 PipeWire / WirePlumber 配置，也不自动修复其他应用的音量。保护失效时，遥控器会拒绝启动听写。SayAll 仍会创建虚拟音频节点，并在按语音键时切换默认麦克风、松开后尝试恢复，可能影响其他跟随默认输入的应用。

当前测试客户端原有的听写降音量功能曾产生兼容风险，完整方案通过必要的播放保护停用这一触发源。部署后仍需测试音乐播放时连续多次听写、切歌、调音量和语音消息，确认录音期间及结束后其他播放音量均不被改变。音频服务若被另外重启，还要确认客户端重新识别麦克风；本项目安装程序不自动重启音频服务。

出现问题时先阅读[故障排查](TROUBLESHOOTING.md)，不要直接套用其他机器的音频规则或旧日志中的设备编号。需要移除本项目时，按[卸载与回退](../README.md#卸载与回退)保留安装清单并恢复配置。
